Continuation of [[product-roadmap-2026-07]] item #3 ("redesain tampilan website... lebih nendang"). Two separate threads happened the same day — keep them distinct:

**1. Concept mockup, not yet applied to real code**: built a full alternate-direction landing page as a standalone Artifact (not touching the live Next.js site) themed entirely around a **cash-register receipt** — thermal-paper palette (pale green-grey, not the AI-cliché warm cream), tabular monospace for every number, dashed perforation dividers instead of rounded cards, an ink-stamp-style primary CTA, and a live-animating "printing receipt" hero (line items appear one by one, totals update, ends with a LUNAS stamp) instead of a static dashboard screenshot. Dark mode reimagined as an LED cash-register display (phosphor-green digits on near-black) rather than a naive color inversion. Covers real KasirKu content (all 8 features, 3 business types, the 3 real pricing tiers, cross-sell to Kalkulator HPP Desktop and Sistem Akuntansi) — no lorem ipsum. **Status: shown to user for feedback, not yet approved or ported into the actual codebase.** If resumed, check whether the user reacted to this direction before starting from scratch on a new one — the artifact URL was `https://claude.ai/code/artifact/ac007e7b-481d-4888-be1b-cddd517b65e7` (private, machine/session-specific, may not resolve in a future context — ask the user if it's still relevant).

**2. Live-site mobile UX fixes — DONE and shipped 2026-07-16** (`05eecad`), reported by the user after checking the actual production site on their phone (separate from the mockup above, on the real `src/app/page.tsx`):
- **Hero preview was static** (only ever showed the "Dashboard" stat card + bar chart). New `src/app/hero-preview.tsx` (client component) turns it into a 3-slide carousel (Dashboard / Kasir / Laporan — each a distinct realistic mini-mockup of that part of the app) that auto-advances every 3.2s (respecting `prefers-reduced-motion`), supports touch swipe (`onTouchStart`/`onTouchEnd` delta-X threshold 40px), and has clickable dot indicators. Implemented as a CSS-transform sliding track (`translateX(-active*100%)`), not a library.
- **Product/content nav links were invisible on mobile entirely** — a regression from the earlier same-day commit `f3eb589` that bumped Kalkulator HPP/Sistem Akuntansi to `sm:` and Artikel/Rekomendasi Alat to `md:` breakpoints to reduce header crowding, which had the side effect of hiding all 4 on phone-width screens (only reachable by scrolling all the way to the footer). Fixed with new `src/app/home-mobile-nav.tsx` (client component, `sm:hidden`) — a hamburger button positioned in the header immediately before Masuk/Daftar Gratis (per the user's explicit ask, "sebelah Masuk-Daftar Gratis") that toggles a dropdown with all 4 links.
- **Tooling note**: the hamburger button's first `computer`/click-tool click didn't register (`aria-expanded` stayed `"false"`) — same class of plain-onClick-button flakiness already documented in [[test-account-preview]] for the POS PIN pad. Switched to `javascript_tool` `.click()`, which worked, though even then the `aria-expanded` read immediately after the same script's `.click()` call showed stale `"false"` (React state update hadn't flushed yet) — had to read it in a *separate* subsequent `javascript_exec` call to see `"true"`. If a toggle button's state looks unchanged right after a scripted click on this project again, don't assume the click failed — re-query in a follow-up call before concluding it didn't work.

Verified E2E in browser at both mobile (375×812) and desktop viewports: hamburger menu opens/closes and shows all 4 links only below `sm`; carousel auto-advances (confirmed via reading the slide label after time passed) and dot-click navigation works. `tsc`/`eslint` clean, no console errors.

**3. Same carousel treatment extended to `/sistem-akuntansi` — DONE 2026-07-16** (`daec860`): user asked for the same carousel to also appear on the Finance Only marketing page.
