**SUPERSEDED same day, 2026-07-13 — do not rebuild this.** Everything below describes a web-based version (Supabase account + Postgres-backed ingredients/menu + Claude AI price recommendations) that was built, verified E2E, then **fully torn out hours later** on the same day (code deleted, `@anthropic-ai/sdk` uninstalled, tables dropped via `20260713120000_drop_hpp_standalone_tool.sql`). Reason: no ongoing AI cost was acceptable, and the user wants a true one-time-sale product with zero server burden going forward. Current direction is a downloadable desktop app — see [[kalkulator-hpp-desktop]]. Keeping the history below only so a future session understands why `hpp_ingredients`/`hpp_menu_items`/`hpp_recipe_lines` briefly existed and were dropped, and doesn't reintroduce a server-backed+AI version without re-confirming with the user first.

Roadmap backlog item #1 ([[product-roadmap-2026-07]]) — "Kalkulator HPP dijual terpisah" — this web version was **shipped & verified E2E 2026-07-13**, then reversed same day. Full standalone tool at `/kalkulator-hpp/daftar` (signup) → `/kalkulator-hpp/app` (authed workspace), separate from the free one-shot public calculator at `/kalkulator-hpp` (which still exists unchanged — the extra CTA that briefly linked to `/kalkulator-hpp/daftar` was also removed).

**Architecture — shares Supabase Auth, not a new auth system**: signup at `/kalkulator-hpp/daftar` sets `user_metadata: { hpp_tool_only: true }`. `src/app/dashboard/page.tsx` checks this flag before its `redirect("/onboarding")` for zero-business users — flagged users go to `/kalkulator-hpp/app` instead, skipping the "create a store" flow entirely. Login still goes through the normal `/login` page (same Supabase Auth, no separate login UI needed). No changes to `src/proxy.ts` were needed — only `src/lib/supabase/middleware.ts`'s public-path check needed a fix: the old `startsWith("/kalkulator-hpp")` would have wrongly made `/kalkulator-hpp/app` public too, so it's now `pathname === "/kalkulator-hpp" || pathname.startsWith("/kalkulator-hpp/daftar")` — a real bug caught during implementation, not part of the original plan.

**Data model**: 3 new tables, scoped by `user_id = auth.uid()` directly (no `businesses`/`owns_business` involved — deliberately outside the normal tenant model) — `hpp_ingredients`, `hpp_menu_items` (with `ai_recommended_price`/`ai_rationale` columns), `hpp_recipe_lines` (denormalized `user_id` on this table too so RLS stays a flat `using (user_id = auth.uid())`, no subquery join). Migration `20260713110000_hpp_standalone_tool.sql`, applied and verified same day.

**AI integration — genuinely new to this codebase** (confirmed greenfield via the `claude-api` skill before building): `src/lib/ai/price-recommendation.ts`, model `claude-opus-4-8`, `thinking: {type:"adaptive"}` + `output_config: {effort:"medium", format:{type:"json_schema",...}}` for a guaranteed-valid JSON response (no Zod added — raw JSON schema to avoid a second new dependency). Only new npm dependency: `@anthropic-ai/sdk`. `ANTHROPIC_API_KEY` lives in `.env.local` (user added it themselves 2026-07-13, created with **no expiration** at platform.claude.com/settings/workspaces/default/keys — deliberately not the short-lived option, since a server-side feature key expiring would silently break the feature).

**Known state as of 2026-07-13**: the Anthropic API key is live and requests reach the API successfully (confirmed via a real 400 response, not a connection/auth failure), but the workspace has **$0 balance** — "Paket Free... Akses evaluasi" — so `requestAiPriceRecommendation` currently returns the friendly error "Saldo API key Anthropic kamu habis — isi dulu di console.anthropic.com (Plans & Billing)". User needs to add funds via that page's "Tambah dana" before the AI recommendation actually returns a price — everything else (ingredient/menu CRUD, HPP/margin math) works today without it. `src/lib/ai/price-recommendation.ts`'s `describeAiError()` maps `Anthropic.AuthenticationError`/`RateLimitError`/`BadRequestError` (specifically the "credit balance" message) to Indonesian-language friendly errors instead of raw SDK JSON dumps.
